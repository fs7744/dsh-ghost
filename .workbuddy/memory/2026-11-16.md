## 非安装版（免安装包）本地打包脚本

- 需求：反复本地验证测试，要「非安装版」。新增 `scripts/pack-win-portable.mjs`（根脚本 `pack:win` / `pack:win:fast` / `pack:win:exe`），产物在 `out/win-portable/`：`win-unpacked/`（免安装目录）+ `dsh-ghost-<v>-win-x64.zip`（解压即用）+ 可选单文件 `-portable.exe`。不写注册表、不碰更新 feed、不污染 CI 的 `out/shell-release/`。
- 配置真源仍是 `build/electron-builder.yml`：脚本读 YAML 后改写 `directories.output` / `win.target` / 压缩级别，输出 JSON 配置再喂给 electron-builder，不另起一份配置。
- **踩坑 1：winCodeSign 永远下不动也解不开。** electron-builder 打包 Windows 要用 winCodeSign 里的 rcedit 改 exe 资源：①要从 GitHub 下载，本机代理 502；②解压需要「创建符号链接」权限，本机 symlink 直接 EPERM（非管理员/未开开发者模式），7za 必然 exit 2。四种绕法都试过（本地 HTTP 镜像喂缓存归档、固定端口让哈希稳定、预置解压目录、手工跑 rcedit），最终解法是**关掉 `win.signAndEditExecutable`**，改用缓存里已解压好的 `rcedit-x64.exe` 自己写图标与版本信息 —— 零下载、零特权。
- **踩坑 2：zip 里要是没图标的 exe。** electron-builder 一次跑完 dir+zip 时，zip 在 rcedit 之前就生成了。改成三步：先 `--win dir` → rcedit 补图标 → 再 `--win zip portable --prepackaged <win-unpacked>` 从打好图标的目录出压缩包/便携版。
- **踩坑 3：spawnSync 会把本地 HTTP 镜像饿死**（同一进程的事件循环被堵死 → 镜像永不应答 → 下载挂死），凡是「进程内起服务 + 再 spawn 子进程」都要用异步 spawn。
- **踩坑 4：electron-builder 每次都要清空 win-unpacked**，上一次残留文件被占用就整包失败。脚本先删（5 次重试），删不掉就换 `out/win-portable-2` 继续，不让残留卡死构建。
- 运行时：`build/runtime/node_modules`（约 580MB / 201 个顶层包）按 `manifest.json` 里的 source 判复用，首次跑 `prepare-runtime --apply` 复制；`--skip-runtime` 出不带运行时的快速版（368MB，只能看 UI，宿主起不来）。
- 实测：完整包 win-unpacked 1505.9MB / 94875 文件、zip 479.5MB；带运行时首次 12m37s（含复制运行时），复用后 8m45s；无运行时 368MB 目录 + 146MB zip。打包后的 exe 能起来（写 settings.json / install-id / state/runtime.lock，前台跑 40s 不退出），zip 内 exe 的版本信息已是 dsh-ghost 0.0.0。
- 已知环境噪音：IDE 会独占打开 `out/**/app.asar`（不带 FILE_SHARE_DELETE），导致该目录删不掉；本机（非管理员）也无法创建符号链接。
