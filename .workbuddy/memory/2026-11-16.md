- 浏览器扩展：apps/extension（manifest/background/sidepanel），设备码式配对——应用显示 6 位码（一次性、5 分钟），扩展 POST {appUrl}/extension/pair → 壳用宿主 token 换 Cookie，只把 Cookie 名值给扩展（token 不进扩展），扩展写进 chrome.cookies 后用 credentials:'include' 调宿主 API（session/create|prompt|page）。
- 桌面端设置页新增「浏览器扩展」区：显示应用地址（location.origin）与配对码。

## 「当前页面」桥：扩展驱动用户当前标签页

- 补上上轮缺口：Playwright 引擎跑在独立临时画像（看不见用户登录态），要操作用户当前已登录页面，
  必须由扩展用 chrome.debugger 驱动**当前标签页**，并加一条模型↔扩展的命令通道。
- 通道：模型 → 宿主排队命令 → 扩展轮询取（ghostPage/next 长轮询 20s）→ CDP 执行 → 回传（ghostPage/result）→ 唤醒模型工具（60s 超时给���话原因）。宿主不能反向调用扩展，所以扩展是主动轮询方。
- 新模型工具：page_read（标题/网址/可见文本）、page_click（可见文字或 CSS 选择器）、page_fill、page_screenshot（base64 回传后宿主落盘）。
- 扩展侧：发消息前自动刷新页面快照并上报（ghostPage/register），所以模型知道「当前页面」是什么。
- 踩坑：取命令时不能从队列里 shift 掉（回传时找不到人唤醒）——改为 pending + inflight 两段队列。
- 安全：不用注入脚本（走 CDP，页面看不见我们），但浏览器会显示「正在被调试」提示条，我们不隐藏；只在用户发消息时采集页面内容；只对「当前活动标签页」操作。
