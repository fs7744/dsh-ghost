# 浏览器扩展：在任意页面里直接和 agent 对话

> 回答「支持直接在浏览器插件 AI 会话吗」——**支持**：一个 Chrome/Edge MV3 扩展，
> 侧栏里就能和本机 dsh-ghost 对话，不用切回应用。

## 0. 怎么用（三步）

1. **应用里出码**：设置 → 浏览器扩展 → 「生成配对码」，记下 6 位码；
   同一页有「应用地址」（如 `http://127.0.0.1:51234`）。
2. **加载扩展**：Chrome/Edge → `chrome://extensions` → 打开「开发者模式」→
   「加载已解压的扩展程序」→ 选仓库里的 **`apps/extension`** 目录。
3. **侧栏配对**：点扩展图标打开侧栏 → 填「应用地址 + 配对码」→ 配对成功后直接聊天。

## 1. 配对为什么这么设计

- **设备码式**：应用显示 6 位码，用户手动输入扩展。**本地任何进程都不能凭空配上**——
  不能因为「在 localhost 上」就默认信任。
- **一次性 + 5 分钟过期**：码用过即废。
- **token 不进扩展**：壳用自己的 token 跟宿主换 Cookie，只把 **Cookie 名值**给扩展，
  由扩展写进浏览器（`chrome.cookies`），之后所有请求用 `credentials:'include'`。
  扩展里**永远拿不到宿主 token**。

## 1.5 「当前页面」：扩展驱动**你正在看的那个标签页**

上一步的缺口（扩展不自动带页面内容）已经补上——而且是按你要的两个场景补的：
「在当前页面点查看新闻」「测一套考试系统的流程」这类**必须作用在用户当前页面**的动作。

### 怎么做的

浏览器自动化的 Playwright 引擎跑在**独立临时画像**里：干净、安全，但**看不见你的登录态**。
要操作你当前那个已登录的页面，就得让扩展用 `chrome.debugger` 驱动**当前标签页**，
并且有一条从模型到扩展的命令通道：

```
模型 ──page_click / page_fill──▶ 宿主（把命令排队）
                                    │
扩展（chrome.debugger 挂在当前标签页）◀── 轮询取命令 ──┘
      │ 执行（Runtime.evaluate / Page.captureScreenshot）
      └── 回传结果 ──▶ 宿主 ──▶ 模型
```

扩展是**主动轮询**方：宿主没法直接调用浏览器扩展（没有反向通道），所以命令进队列、扩展来取；
模型侧的工具会等结果（60 秒超时，超时给的是人话原因，不是挂死）。

### 新增的四个模型工具

| 工具 | 作用 |
|---|---|
| `page_read()` | 读当前页面：标题、网址、可见文本 |
| `page_click(target)` | 点当前页面：给**可见文字**（如「查看新闻」）或 CSS 选择器 |
| `page_fill(target, value)` | 给当前页面的输入框填值 |
| `page_screenshot()` | 当前页面截图，存到工作区并返回路径 |

发送消息前，扩展会自动**刷新一次页面快照**并上报——所以你说「在当前页面点查看新闻」时，
模型已经知道当前页面是什么、上面有没有「查看新闻」这个字样。

### 两个场景怎么走

- **「在当前页面点击查看新闻」**：模型先 `page_read()` 看当前页面（找到「查看新闻」按钮），
  再 `page_click("查看新闻")` → 扩展在**你这个标签页**里点 → 结果回到对话。
- **「测一套考试系统的流程，结果对不对」**：模型可以 `page_click` / `page_fill` /
  `page_read` 一步步走流程并读取结果（`page_read` 拿的是当前页面的可见文本，
  可以读到题目、得分、提示）。因为是在**你的已登录页面**里做，所以登录态、验证码前的
  步骤都是现成的。

### 边界与代价（说清楚）

- **`chrome.debugger` 会在标签页顶部显示「正在被调试」提示条**——这是浏览器的可见提示，
  我们不隐藏它（隐藏调试提示本身就越界了）。
- 扩展**只在用户明确发消息时**采集页面内容；不会在后台偷偷读页面。
- 「当前页面」= **最近一次上报的活动标签页**（本地单用户场景下的取舍）；
  多标签并发操作属于未支持。
- 页面内容会上报给**本机**宿主（不是云端），进入会话上下文——和把页面内容复制给模型
  是同一件事，不新增外泄面。
- 命令通道是**单条串行**的：模型发一条、扩展执行一条、回传后再发下一条。

## 2. 扩展里能做什么

- 在任意页面旁边开侧栏，与**本机**的 agent 对话（跑的是你本机的模型与工具链，不是云端）；
- 会话是扩展自己建的（`session/create`），与主界面互不干扰；
- 发送后轮询 `session/page` 取回复（宿主没有给扩展推消息的通道，轮询简单可靠）。

## 3. 文件与端点

| 文件 | 作用 |
|---|---|
| `apps/extension/manifest.json` | MV3 清单（侧栏 + `cookies` + `storage` 权限） |
| `apps/extension/background.js` | 配对、调用宿主 API（typert 网关的 client-request 形状） |
| `apps/extension/sidepanel.html/.js/.css` | 侧栏界面 |
| `apps/shell/src/extension-pairing.ts` | 配对码（一次性、5 分钟） |
| `apps/shell/src/electron-static.ts` | `POST /extension/pair` 路由（换地址 + Cookie） |
| `apps/shell/src/main.ts` | 用宿主 token 换 Cookie |

宿主侧用到的端点只有三个：`session/create`、`session/prompt`、`session/page`。

## 4. 安全边界

- 扩展**只能**调本机宿主 API，且必须先配对；
- 配对码一次性、5 分钟过期；
- 宿主 token 不出壳、不进扩展；
- 扩展只请求 `http://127.0.0.1/*`（`host_permissions` 限定回环）；
- 扩展不注入页面、不改页面 DOM——它只是侧栏里的一个聊天口。

## 5. 已知边界

- **只支持 Chrome/Edge 114+**（侧栏 API 要求）；
- 扩展与主界面是**两个会话**（各自的 `sessionId`），不是同一个上下文的两个窗口；
- 宿主重启后端口会变，扩展需要**重新配对**（地址与 Cookie 都要换）；
- 「当前页面」只有**一个**（最近上报的活动标签页），多标签并发操作未支持；
- 宿主重启后要重新配对。
