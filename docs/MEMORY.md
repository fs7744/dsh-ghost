# 记忆与进化

> 学三家的成熟做法，不发明新概念：**Claude Code 的分层文件记忆**、**Claude 产品的可见可编辑记忆**、**WorkBuddy 的单文件 Memory Block**（下面有实测证据）。
> 一句话：**记忆是文件，不是数据库；常驻的必须极小；写入有门槛；人永远能看见和删掉。**

## 0. 三家做法（含实测）

| 来源 | 做法 | 我们取什么 |
|---|---|---|
| Claude Code | 分层 `CLAUDE.md`（企业 / 用户 / 项目 / 本地），按目录树自动加载，进 git 可评审 | **分层 + 进 git + 按需加载** |
| Claude 产品 | 跨会话记忆，用户可查看/编辑/关闭；Projects 有独立知识 | **默认可见可编辑，有总开关** |
| Anthropic Agent Skills | 完整 skill 包：`SKILL.md` + `scripts/` + `references/` + `assets/`，三级渐进披露 | **skill 是包，不是一篇文档** |
| WorkBuddy（本机实测） | `~/.workbuddy/memory/<uid>_memory.md`，17 行 / 254 字节，结构是 `# User Memory Profile` + `## Memory Block`，带 `.bak` 备份 | **单文件 + 极小常驻块 + 备份** |

**WorkBuddy 那个 254 字节是最有说服力的一点**：它的"用户记忆"就是一个小到能整段常驻的块，不是一堆条目文件。我们照这个规模定预算。

## 1. 四层记忆 + 一个索引

| 层 | 存什么 | 存在哪 | 谁写 | 何时进上下文 |
|---|---|---|---|---|
| **L0 工作记忆** | 当前会话的上下文 | harness 会话 | 自动压缩 | 始终 |
| **L1 会话记忆** | 一次任务的过程与结论 | harness session（JSONL） | 自动 | 恢复会话时 |
| **L2 项目记忆** | 项目约定、构建命令、踩过的坑 | 仓库内 `GHOST.md` + `.ghost/memory/*.md` | 模型提议 → 人确认 → git | 索引常驻，条目按需 |
| **L3 用户记忆** | 偏好、习惯、语言、禁忌 | `%APPDATA%/ghost/user-memory.md` | 模型自动写（有门槛） | **常驻，≤ 2KB** |
| **L4 团队记忆** | 共享约定、剧本库 | 仓库 `playbooks/`、`docs/` | 人（走 PR） | 按需 |

`L2` 的结构与 skill 完全同构——**同一套"索引常驻 + 正文按需"机制，复用两次**。这是省 token 的地方，也是实现简单的地方。

## 2. 四条铁律

1. **记忆是文件**。可 diff、可评审、可回滚、可 `.bak`。绝不进数据库黑盒——黑盒记忆等于不可调试的魔法。
2. **常驻部分必须小**。L3 ≤ 2KB（对标 WorkBuddy 的 254 字节）；超了就拆成"索引 + 条目文件"，索引留在常驻块里。
3. **写入有门槛**。只写"跨会话仍成立、且下次会改变行为"的事实。三个过滤问题：
   - 是稳定事实，还是一次性上下文？
   - 下次真的会用到吗？
   - 来源是哪次任务？（没来源的不写，无法追溯等于谣言）
4. **人永远能看见和删掉**。界面上有「记忆」页：分组展示、逐条编辑、逐条删除、一个总开关。默认开启但不默认全屏展示——不打扰。

## 3. 写什么、不写什么

| 写 | 不写 |
|---|---|
| 用户偏好（"别用 emoji"、"中文回答"） | 一次任务的临时路径 |
| 项目约定（构建命令、目录结构、发布流程） | 可从代码直接读出的东西 |
| 反复踩的坑（"这个包 peer 冲突要宽容"） | 密钥、令牌、个人信息 |
| 已确认的决策（"只跟最新 harness"） | 未确认的猜测 |

> 最后一条最容易犯：把"我们讨论过 A 方案"写成"决定用 A"。**只写确认过的。**

## 4. 进化：三级 + 人闸 + 度量

「进化」= 系统不改代码就改变自己的行为。分三级，**每一级都必须有人闸**。

| 级 | 触发 | 产物 | 生效方式 |
|---|---|---|---|
| **记忆进化** | 同一个错误出现 3 次 | 一条"约束"写进 L2 项目记忆 | 模型提议 → 人确认 |
| **剧本进化** | 任务失败/返工，且原因可归到某个节点 | 对该节点的 `.flow` 改动 | diff + 人确认 + git |
| **技能进化** | 临时脚本连续 2 次跑通 | 沉淀进 skill 包的 `scripts/` | PR |

### 4.1 三条防漂移规则

1. **禁止运行时静默改写自己的提示词/剧本**。一切进化走 PR——否则系统会在没人注意时变成另一个东西。
2. **无度量不合并**。每次进化记录 before/after：完成率、token 用量、工具调用数、返工次数。没有数字的"改进"是随机游走。
3. **可回滚**。进化的产物就是 git 里的文件，回滚 = revert。

### 4.2 度量从哪来

- 每次任务结束写一条 `run` 记录（Ticket id、耗时、token、工具调用数、是否返工、是否越权）。
- 这些数据落在 `.ghost/telemetry/runs.jsonl`（本地，不外传），供「进化建议」使用。
- 界面上一个「进化」页：列出候选改动 + 指标对比 + 一键接受/拒绝。

## 5. 与 skill 包的关系

记忆和剧本共用同一套加载器，但角色不同：

| | 剧本（skill 包） | 记忆 |
|---|---|---|
| 回答什么 | **怎么做**（流程） | **是什么 / 偏好什么**（事实） |
| 谁维护 | 人 + AI 编辑图 | 模型自动写，人可改 |
| 变更频率 | 低（一次任务反复用） | 高（每次任务都可能加一条） |
| 加载 | 索引常驻，正文按需 | 小常驻块 + 条目按需 |

**不要混**：把"怎么做"塞进记忆，会把常驻块撑爆；把"用户偏好"写进剧本，会让剧本随人变形。

## 6. 预算表（估算）

| 内容 | 常驻 | 按需 |
|---|---|---|
| skill 索引（每个 name + description） | ~20 token × N | |
| 用户记忆块（L3） | ≤ 600 token（2KB） | |
| 项目记忆索引（L2） | ~30 token | 条目正文每次 ~100 |
| 剧本正文 | | ~110 token |
| 剧本 references | | 400–600 / 文件 |
| 脚本输出 | | 40–80 / 次 |

按 5 个剧本 + 1 个用户记忆块算，常驻约 **750 token**。这比"把所有流程和约定写进系统提示"（通常数千 token）小一个数量级。

## 7. 记忆界面与总开关（C10-03 已落地）

界面**不直接读文件**：`memory-plugin` 注册 `ghostMemory/list|read|write|remove|status|toggle` Remote，
与模型的 `memory_*` 工具共用同一个 `MemoryStore` 和写入门槛，所以「模型记了什么」在界面里一定看得到。

- **分组查看**：按 `updated` 分「今天 / 近 7 天 / 更早 / 未标注时间」，组内按名称排序；正文按需读取。
- **逐条编辑 / 删除**：编辑复用 `write`（同名覆盖、`source: desktop-ui`），仍过 gate；删除同步索引。
- **一个总开关**：落盘到 `<root>/settings.json`，宿主重启后仍生效。关闭后**模型侧 `memory_write` 与界面侧 `ghostMemory/write` 都被拒**，已写的仍可读、可删——它是「别再记新的」，不是「把记忆藏起来」。
- 验收：`npm run verify:memory-ui`（真实宿主）、`npm run test:memory-view`（5 用例）、
  `npm run test:plugin`（4 用例，含关闭后模型写不进去）。

## 8. 三级进化与度量（C10-05～07 已落地）

`packages/evolution` 是纯模块（零 DOM、零网络、依赖可注入），`memory-plugin` 只做一层薄 Remote：`ghostEvolution/list|propose|approve|reject|metrics`。

- **记忆进化**：同一错误 / 返工第 3 次才生成「升为约束」提案；`list` 可查看、`approve` 才写进 L2 项目记忆、`reject` 不写任何文件。提案本身落盘为文件，可 `git revert`。
- **剧本与技能进化**：返工归因到 `.flow` 节点 → 生成带 before/after 度量的修改提案；脚本连跑通 2 次 → 生成沉淀进 `scripts/` 的提案。**两者都只落盘，不自动改仓库**。
- **度量**：`runs.jsonl` 记每次的完成率 / token / 工具数 / 返工与时间戳，`metrics` 汇总出 before/after 看板数据。

验收：`npm run test:evolution`（19 用例，含「驳回不落盘」）、`npm run verify:evolution`（真实宿主 21 项：三次返工 → 提案 → 批准 → `ghostMemory/read` 读到 L2 正文 → 驳回分支 → `runs.jsonl` 落盘，并清理测试数据）、`npm run verify:init`（`/init` 生成的 `GHOST.md` 草案不覆盖既有文件）、`npm run verify:compaction`（压缩策略配置）。

> 红线不变：**禁止运行时静默改写自己的提示词、剧本或技能**；每级都要人闸 + git + before/after 度量。
